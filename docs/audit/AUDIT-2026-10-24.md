# Not-Happy-Jan — Full Code Audit

**Date:** 2026-10-24 · **Scope:** all of `src/nhj/` (~7,500 lines Python), `install.sh`,
`config/default.yaml`, `hooks/`, `integrations/`, `tests/` (35 files), CI, packaging.
**Method:** every cited file was opened and read; the test suite and linters were executed
(see §7 for raw results). Threat/resource model assumed throughout: single-user,
local/LAN, runs beside an interactive coding agent.


> **Note (added when moved to `docs/audit/`):** file and line references are as of the audit run on 2026-10-24, before the review fixes merged in PR #43, so some line numbers have shifted. Follow-up work is tracked in issues #44 to #50.

---

## 1. Executive summary

NHJ is in better shape than most feature-driven projects at this stage. The hard parts —
the file queue's claim/ack/poison protocol, the single event validator, per-adapter
isolation, localhost-by-default servers, the bank→cache→live fidelity ladder — are done
properly and are covered by 375 passing tests.

The debt is concentrated in four places:

1. **Three real concurrency bugs** in the cross-process state files (§3, B1–B3), all in
   `hook.py` and `inference_muzak.py`, all fixable by reusing the locking pattern that
   `state.py` already implements correctly.
2. **Hook-path cost that grows with session length.** The Stop hook re-reads the entire
   transcript file every 120 ms while waiting for the final message flush (§4, R1). On a
   long session this is the single largest avoidable cost NHJ imposes on the agent.
3. **No config/state schema.** ~75 environment variables and a deep-merged YAML config
   are trusted at point of use. This is the main blocker for spec-driven development:
   there is an event contract (`event.py`) but no config contract, no state-file
   contract, and no written spec for hook payloads per agent CLI (§5, §6).
4. **Verification gaps:** CI runs macOS only while the README claims Linux support;
   the lint gate is not reproducible (lockfile vs installed ruff disagree, and the
   newer ruff reports 270 findings); one queue test is flaky under the full suite (§7).

Against the field (§8), NHJ is the most capable multi-sensory tool audited — nothing
else combines haptics, pixel displays, a Vestaboard, a physical bell, hold music, and
cloned voices. Its main competitive gap is the entry price of live speech: AgentVibes
speaks arbitrary text on CPU with Piper/Kokoro or the OS voice at zero setup, while
NHJ's live path wants ~5 GB of local models. A cheap CPU TTS tier is the highest-value
feature adoption.

A draft [`SPEC.md`](https://github.com/guruswami-ai/not-happy-jan/blob/main/SPEC.md) derived from the current contracts accompanies this audit.
§9 gives the prioritised plan to become spec-driven.

## 3. Correctness and security findings

Severity assumes the single-user local/LAN threat model. **P1 = fix before next
release, P2 = fix soon, P3 = backlog.** No P0 (nothing here loses user data or exposes
the machine by default).

### Bugs

- **B1 (P1) — Stop-hook ledger is neither locked nor atomic.**
  `_seen_set` does a read-modify-write with a bare `write_text`
  ([hook.py:82](https://github.com/guruswami-ai/not-happy-jan/blob/main/src/nhj/hook.py#L82)). Two sessions' Stop hooks
  (or a hook racing `prompt_hook.py:72`) can clobber each other's entries or expose a
  half-written file; `_seen_get` then returns `""` and the fire-once guarantee is lost
  (duplicate speech) or a baseline is lost (missed marker). `state.py:49` already
  implements the correct flock+unique-temp pattern — this file should use it.

- **B2 (P1) — Muzak state writes race on a fixed temp path.**
  `_write` always uses `*.json.tmp`
  ([inference_muzak.py:64](https://github.com/guruswami-ai/not-happy-jan/blob/main/src/nhj/inference_muzak.py#L64)), and
  `start()`, `stop()`, and `_any_busy()`'s eviction call `_write` *outside* the
  `_update` lock (lines 147, 207, 233). Concurrent hooks plus the controller loop can
  interleave two writers on the same temp file. `_any_busy()` also mutates state as a
  hidden side effect of a getter, called from the controller loop, the worker
  (`orchestration.py:42`), and the audio adapter (`audio.py:279`) — a read that writes,
  unlocked. Fix: unique temp names (as `state.save` does) and route every mutation
  through `_update`.

- **B3 (P2) — Same-millisecond filename collisions in the audio spool.**
  Mixer events are named `{ms}-{pid}.json`
  ([inference_muzak.py:294](https://github.com/guruswami-ai/not-happy-jan/blob/main/src/nhj/inference_muzak.py#L294)) and
  temp WAVs `{ms}.wav` ([adapters/audio.py:70](https://github.com/guruswami-ai/not-happy-jan/blob/main/src/nhj/adapters/audio.py#L70)).
  Two clips submitted in the same millisecond by one process silently overwrite each
  other — most plausible for the off-hold click + return clip + result burst. The queue
  manager already solves this exact problem (`queue_manager.py:103`, ts+pid+seq+rand);
  reuse that naming.

- **B4 (P2) — Remote Stop-hook dispatch has no timeout.**
  `_fire_remote` (`hook.py:151`) runs an async MCP call with no deadline. A hung LAN
  daemon hangs the Stop hook until the agent's 30 s hook timeout
  (`hooks/hooks.json:12`) kills it — visible as the agent "sticking" at end of turn.
  Wrap in `asyncio.wait_for` (≤5 s) and fall back to logging.

- **B5 (P2) — Queue lease can expire under a live worker.**
  Claim lease is 30 s (`queue_manager.py:44`), but one dispatch can legitimately take
  longer: `servers.ensure` waits up to 45 s (`servers.py:129`) *plus* LLM timeout 8 s
  (`boganify.py:127`) *plus* TTS timeout 30–60 s (`audio.py:166,203`). A second
  `claim_next` (e.g. `get_next` back-compat path, or a worker respawned after its
  pidfile was lost) would treat the still-running claim as expired and double-dispatch.
  Either heartbeat the claim mtime during dispatch or raise the lease above the
  worst-case dispatch budget and document that budget in the spec.

- **B6 (P3) — Worker re-validates nothing.** `worker.py:41` does
  `int(task.get("vibe_level", 5))` and friends; a malformed queue file (any producer
  other than MCP/hook — `QueueManager.add` itself validates nothing,
  `queue_manager.py:98`) raises, gets nacked, retried 3×, then quarantined. Contained,
  but wasteful. Validate once in `add()` via `event.validate` and once after `_parse`.

- **B7 (P3) — Cache writes are not atomic.** `_save_and_cache` writes WAV bytes
  directly (`audio.py:238`); a crash mid-write leaves a truncated file that
  `cache_hit` accepts (it only checks size ≥100 bytes, `audio.py:149`). Write to temp
  + rename, as the queue does.

- **B8 (P3) — Marker anti-discussion guard is thin.** The backtick check
  (`hook.py:237`) only inspects the immediately adjacent characters; markers inside
  fenced code blocks or spaced inline code still fire. Acceptable trade-off, but it
  should be a documented spec behaviour, not an accident (see SPEC §3).

### Security

- **S1 (P2) — Unauthenticated LAN surfaces (opt-in, but silent).** Binding the MCP
  server to `0.0.0.0` (`mcp_server.py:80`, `--listen`) lets anyone on the LAN call
  `nhj_vibe` with arbitrary text to be spoken aloud and pushed to displays/bells.
  The TTS server likewise has no auth and no text length limit
  (`tts_server.py:113` — `GenReq.text` unbounded, one request can hold the single
  GPU executor for minutes). Defaults are safe (127.0.0.1); the risk is that the
  opt-in says nothing about it. Minimum: shared-secret header option + `max_length`
  on TTS text (e.g. 500 chars) + a warning in `nhj install-mcp-service` output.

- **S2 (P3) — Logs contain user content and grow forever.** The Stop hook logs the
  first 60 chars of every fired message and the last 50 chars of the assistant turn
  (`hook.py:221,262`). No rotation exists anywhere (searched: no `rotat/truncate`
  in `src/nhj`). `hook.log`/`worker.log` grow unbounded and preserve fragments of
  agent output indefinitely. Add size-based rotation (e.g. 1 MB × 3) and log
  intent/length instead of message text by default.

- **S3 (P3) — `curl | bash` installer is the front door.** README line 58. Standard
  for the genre, and `install.sh` is no-sudo/reversible, but it executes `main`
  branch code. Pin the documented one-liner to a release tag and publish a checksum.

- **Positive notes.** `secret_scan.py` is correctly category-only (match object is
  discarded, line 55); no `shell=True`/`eval`/`verify=False` anywhere in `src/`
  (searched); queue dir is `chmod 700` with 0600 files; CodeQL + gitleaks run in CI;
  config parse errors fail loud instead of silently defaulting (`config.py:35`).

## 4. Resource use and performance

Budgets that matter: (a) latency added to the agent's turn, (b) idle CPU/RAM on the
dev machine, (c) model RAM when live.

- **R1 (P1) — Transcript polling is O(file × polls).** While waiting for the final
  assistant message to flush, the Stop hook calls `_read_last_assistant_text` every
  120 ms for up to 3 s (`hook.py:199-217`); that function reads and JSON-parses
  **every line of the transcript from byte 0** (`hook.py:101`). `prompt_hook.py:71`
  does a full read once per prompt too. Import cost is fine (measured: `nhj.hook`
  imports in ~30 ms, `nhj.worker` in ~90 ms). The fix is a tail read: seek to
  `max(0, size − 256 KB)` and/or remember the last-read offset per session in the
  ledger. Expected effect: hook CPU becomes constant instead of growing all session.

- **R2 (P2) — Mixer controller busy-polls files at 20 Hz.** The controller loop runs
  every 50 ms while playing (`duck_player.py:793`) and every iteration reads the
  muzak state file (`M._read`, line 745), calls `duck_gain()` (another full file
  read, `inference_muzak.py:273`), and scans the event spool dir (`pump_events`).
  While idle it still loops at ~8 Hz. A 250 ms tick with the spool check kept at
  50 ms (or one combined state read per tick) cuts this ~5× with no audible change.

- **R3 (P3) — Output-device watcher spawns subprocesses forever, including on
  Linux.** `_watch_device` wakes every 4 s (`duck_player.py:699`) and calls
  `SwitchAudioSource`/`system_profiler`; neither exists on Linux, so it spawns a
  failing subprocess every 4 s for the controller's lifetime. Gate to macOS
  (`sys.platform == "darwin"`); `NHJ_FOLLOW_DEVICE` should also default off when
  `NHJ_OUTPUT_DEVICE` is pinned.

- **R4 (P2) — "Minimal" still installs the heavy stack.** `install.sh --minimal`
  skips only the `[server]` extra (install.sh:147). The base dependencies are
  unconditional (`pyproject.toml:27`): `av`, `scipy`, `numpy`, `sounddevice`,
  `hidapi`, `fastmcp` install everywhere — hundreds of MB of wheels even for a
  hooks+bank install on a headless box. Move `av/sounddevice/scipy` to an
  `[audio]` extra, `hidapi` to `[haptic]`, `paho-mqtt` to `[displays]`, keeping
  core at `pyyaml/typer/rich/requests/python-dotenv`. Adapters already fail-soft
  via `load_adapters`, so the split is mostly packaging.

- **R5 (P3) — Worker recovery shells out to `ps` per claim file.**
  `_pid_alive` → `_is_zombie` runs `ps` (`queue_manager.py:51`) inside
  `_recover_stale`, which runs on every `claim_next` — i.e. once a second while the
  worker idles. On Linux read `/proc/<pid>/stat` directly; reserve `ps` for macOS.

- **Positive notes.** On-demand server mode genuinely reaches ~0 idle RAM for
  models (600 s reap, `servers.py:37`); the worker self-exits after 30 s idle;
  the message cache is LRU-capped at 300 and the temp-WAV spool pruned to 80;
  the busy-set has both a TTL and dead-owner eviction so music can't stick on
  forever. The one remaining unbounded growth is the logs (S2).

## 5. Architecture and code quality

- **Q1 (P1) — No config schema.** `config.py` guarantees only "top level is a
  mapping". Everything else — types, ranges, enum values, required keys — is trusted
  at point of use across ~40 call sites, and unknown keys are silently ignored (a
  typo'd `adapters:` or `routing:` key does nothing, loudly). The merged config is
  also frozen at import (`_CFG = load_config()`, `config.py:93`): long-lived
  processes (MCP daemon, mixer) never see edits, which is observable behaviour that
  belongs in the spec. This is the single biggest spec-driven gap. A pydantic model
  (pydantic already arrives via fastmcp/fastapi) with `extra="forbid"` would turn
  the whole class of silent misconfiguration into startup errors.

- **Q2 (P2) — Configuration surface is ~3× the documented surface.** 75+ distinct
  env vars are read in `src/nhj` (counted), while `docs/configuration.md` mentions
  16 and `.env.example` 18. Precedence per setting is decided ad hoc at each read
  site (env vs YAML vs state). The spec needs one table: setting → type → default →
  sources in precedence order → read-live or read-at-import.

- **Q3 (P2) — Fail-soft has become fail-silent.** 92 `except Exception` sites in
  `src/nhj`, 27 of which are bare `pass` (counted). Much of it is right — a feedback
  toy must never break a coding session — but `load_adapters`
  (`adapters/__init__.py:29`) swallowing *instantiation* errors means a broken
  adapter vanishes with no trace anywhere, and several audio-path failures print to
  a stderr nobody reads (worker stderr goes to `worker.log` only via the spawn
  redirect). `resources.debug()` exists for exactly this and is used in only a few
  places. Policy for the spec: hooks/worker stay fail-soft to the agent, but every
  swallow gets a `resources.debug` line; `nhj status` should surface "adapter X
  failed to load: reason" by recording load errors.

- **Q4 (P3) — Two monoliths.** `cli.py` (1,518 lines, ~40 commands plus service
  install logic for two platforms) and `duck_player.py` (800 lines: decode, mixer,
  device watching, controller state machine, rave display cycling). Neither needs a
  rewrite; split by existing seams when next touched (`cli/` package by command
  group; `duck_player` → decode / mixer / controller).

- **Q5 (P3) — Platform ceiling is accidental, not declared.** `fcntl` is imported
  unconditionally (`queue_manager.py:27`, `state.py:12`), so NHJ cannot even import
  on Windows, while `servers.py:31` already contains a Windows fallback that
  therefore can never run. `pyproject.toml` classifiers still say
  `Operating System :: MacOS` only, although Linux is documented and supported.
  Decide the supported set in the spec (macOS + Linux, Windows best-effort?) and
  make code, classifiers, and CI match it.

- **Q6 (P3) — Dead/legacy surface adds audit weight.** Legacy flat-phrase characters
  (`characters.py:104`), legacy routing keys (`characters.py:268`), `get_next`
  read-and-forget (`queue_manager.py:180`), `duck()/unduck()` described in-code as
  "mostly vestigial" (`inference_muzak.py:262`), legacy `~/.config/nhj` read
  fallbacks. Each is cheap alone; together they are the "feature-driven" residue
  the spec should either bless or delete.

`tests/test_event_contract.py`), `docs/AUDIO-STANDARD.md` as a normative audio
document, `docs/ARCHITECTURE.md` as descriptive background, and a release-readiness

- **T1 (P1) — Flaky crash-recovery test.** A test that proves the queue's core
  durability promise cannot be order-dependent. Reproduce with repeated full runs,
  then fix the root: if it's PID reuse making `_pid_alive(dead_pid)` true, that's
  also a product edge — recovery leans on PID liveness first and only falls back to
  the 30 s lease (`queue_manager.py:210`), so a reused PID delays recovery by the
  lease. Storing the worker's start-time alongside the PID (or just trusting the
  lease) closes both.
- **T2 (P1) — Lint gate is not reproducible.** `uv.lock` pins ruff 0.15.16; the
  working `.venv` has 0.17.2; `pyproject.toml` declares `ruff>=0.1.0`. CI runs
  `uv run` (locked, green today), but any lock refresh jumps two minor versions of
  rule defaults and turns CI red with ~270 findings unrelated to the change at
  hand. Pin `ruff==0.15.*` (or consciously adopt the new default set and fix the
  findings — 92 are auto-fixable), and add an explicit `select = ["E9","F"]` so
  intent no longer depends on ruff's changing defaults.
- **T3 (P2) — CI does not cover a claimed platform.** `.github/workflows/ci.yml`
  runs `macos-14` only (Python 3.10 + 3.12), while the README and `docs/linux.md`
  claim Linux support and there is Linux-only code (XDG paths, `/proc` owner-PID
  detection `inference_muzak.py:122`, systemd units). This audit's test run was on
  Linux and passed (bar the flake) — add an `ubuntu-latest` matrix leg to keep it
  that way.
- **T4 (P3) — No coverage or type gate.** No `coverage`/`mypy`/`pyright`
  configuration exists. 280 test functions cover the queue, config, state, worker,
  installer, and event contract well, but `duck_player.py` (800 lines, threads +
  realtime callback) and most adapters have no direct tests. Add
  `pytest --cov=nhj` reporting (not a hard gate yet) so the spec work can target
  the uncovered seams; the mixer's non-audio logic (bus sequencing, spool ingest)
  is testable without hardware via its existing seams.

## 8. Competitive comparison

Sources fetched 2026-10-24: [AgentVibes repo](https://github.com/paulpreibisch/AgentVibes)
(README features/providers sections read in full),
[cc-hooks](https://github.com/husniadil/cc-hooks) (search result),
[claude-code-voice-hooks](https://github.com/shanraisshan/claude-code-voice-hooks)
(search result), [claude-code-tts](https://git.sr.ht/~cg/claude-code-tts) (search
result), and the [vox PR/FAQ](https://github.com/punt-labs/tts) competitor summary
(search result, third-party). NHJ column is from §2 of this audit.

| Attribute | NHJ | AgentVibes | cc-hooks / others |
|---|---|---|---|
| Modalities | Voice + hold music + haptics + LED/LaMetric/Vestaboard + ESP32 bell | Voice + background music + effects | Voice/earcons (cc-hooks); ding/dong per tool use (voice-hooks) |
| Live TTS entry cost | ~5 GB local models (MLX/CUDA) or bundled bank for bare markers only | Zero-config OS voice; Piper 900+ voices & Kokoro on CPU; ElevenLabs optional | Kokoro local (claude-code-tts); multi-provider (cc-hooks) |
| Character system | Severity ladder, per-character dials, custom fine-tuned LLM, zero-shot cloned voices | 19 static personalities, sentiment styles, per-agent (BMAD) & per-LLM voices | Contextual AI messages (cc-hooks) |
| Event granularity | Turn-level (prompt/stop/failure/end/notification) | Turn-level acknowledge/complete | **Tool-level** Pre/PostToolUse earcons available |
| Multi-session | Busy-set music, quiet-while-busy digest, per-project voice gate, source labels | Per-agent voices in a team; per-LLM routing | Largely single-session |
| Remote/SSH | LAN MCP dispatch to a daemon host (sound at the daemon) | **Remote Receiver**: audio returns to your local speakers over SSH | Notification Bell works over SSH (sound only) |
| Platforms | macOS (full), Linux (documented) | macOS, Windows, Linux/WSL, Android/Termux | Varies; plugin-marketplace install (cc-hooks) |
| Config UX | YAML + ~40 CLI commands + natural language via skill | TUI (voice browser with preview) + 50+ commands/MCP | Plugin settings |
| Privacy | 100% local by design; secret guard | Local providers local; ElevenLabs sends text to cloud | Mostly local |

**Worth adopting, in value order:**

1. **CPU TTS tier (Piper and/or Kokoro) + OS-voice tier** between the bank and live
   neural synth. This removes NHJ's biggest adoption cliff: arbitrary message text
   spoken on any machine with no GPU and no 5 GB download. The 3-tier dispatch
   (`audio.py:305`) becomes 4 tiers with no interface change. This also gives
   Windows a path if Q5 is answered with Windows support.
2. **Tool-use earcons (opt-in).** Optional Pre/PostToolUse short sounds on the fx
   bus give "still working" granularity during long silent tool runs, when hold
   music alone can't distinguish progress from a hang. NHJ's mixer already has the
   right bus; the work is two more hook registrations + a rate limiter.
3. **Remote Receiver equivalent.** NHJ's remote mode plays sound at the daemon
   machine; AgentVibes streams it back to the SSH client's speakers. For the
   "agent on a server, human at a laptop" case the latter is the right default.
   The MCP transport NHJ already has can return `audio_b64` the way
   `tts_server.py` already does.
4. **Voice preview/browser UX.** `nhj voices` lists; it cannot audition.
   `nhj voices --preview jan` playing bank+live samples is a day of work on
   existing paths and closes the most visible UX gap vs the AgentVibes TUI.
5. **Per-CLI voice routing.** NHJ routes by project (`gate.py`) and labels by
   host:project; AgentVibes routes by which LLM/CLI spoke. Adding the CLI to the
   event `source` (spec change, §2) enables "Codex sounds different from Claude".

**Deliberately not copying:** cloud TTS (breaks the 100%-local promise that
differentiates NHJ; BYO-endpoint via `boganify`-style config covers users who want
it), and a 900-voice catalogue (NHJ's bet is three characterised voices, not a
library — the CPU tier should ship 1–2 good voices mapped onto the cast).
